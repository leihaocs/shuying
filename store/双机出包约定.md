# 双机出包约定（Mac + Windows）

> 适用对象：**Android 包**。
> iOS 与鸿蒙仍**只在 Mac 出包**，不在本文范围内。
> 制定日期：2026-10-23，基于「家里 Mac + 办公 Windows 共用同一发布密钥」的工作方式。

---

## 一、权限边界

| 事项 | Mac（家里） | Windows（办公室） |
|---|---|---|
| Android 调试包 | ✅ | ✅ |
| Android 正式包（可上架） | ✅ | ✅ |
| iOS 编译、上传、TestFlight | ✅ | ❌ 需 Xcode / Transporter |

| 文档、软著材料 | ✅ | ✅ |

iOS 与鸿蒙的限制来自工具链（Xcode、DevEco 无 Windows 版），是硬约束，不是人为约定。

## 三、六条纪律（必须遵守）

核心原则：**构建自由，发布唯一。**

- 两台机器**随时可以打同一个版本号的包** —— 验证、练习、内部测试都不受限，同版本号的包互相覆盖安装也正常（签名一致）
- **只有上传商店的包才要求版本号唯一**：某个 `+N` 一旦上架，这个 N 就作废，不能再用于另一个上架包

| # | 纪律 | 原因 |
|---|---|---|
| 1 | **构建随意，发布唯一**：两端都能打同一个 `+N` 的包；但同一个 `+N` 只能有一个包进商店 | `versionCode` 的唯一性是商店侧校验，本地怎么打都不影响 |
| 2 | **版本号只在确定要发布时才累加**，日常出包不动 `+N` | 避免版本号无意义膨胀；发布时自己记得 +1 即可 |
| 3 | **发布前 `git pull`，发布后 commit + push 版本号** | 保证两端看到的版本一致、可追溯 |
| 4 | `key.properties` 和 `.jks` **永不入库** | 密钥现在存在于两台机器，泄露面翻倍，不能再扩散到 git |
| 5 | **两端 Flutter 版本保持一致** | 否则同一份代码两端产物不同，出问题无法复现 |
| 6 | 产物放 `dist/`（已忽略），**不入库** | 仓库只放源码与文档 |

## 四、两种出包流程

### A. 日常构建（随时可打，不动版本号）

```bash
git pull                                   # 只同步代码
flutter build apk --debug --flavor direct   # 调试包
flutter build apk --release --flavor direct # 正式包（本地留着，不上传）
```

- 两端都能打同一个 `+N` 的包，互不影响
- 签名一致，所以同版本号的包在手机上可以互相覆盖安装
- **不上传商店，就不会有任何冲突**
- Windows 侧也可用一键脚本：`C:\dev\出调试包.bat`

### B. 发布构建（确定要上架时才做）

```bash
git pull                       # 1. 同步
# 2. 编辑 flutter_app/pubspec.yaml：version: 1.0.0+N
#    N 必须递增到「从未上架过」的新数字
flutter build apk --release --flavor direct   # 3. 出包
git add flutter_app/pubspec.yaml              # 4. 提交版本号
git commit -m "chore: 安卓构建号升至 1.0.0+N（<机器名> 发布）"
git push
```

出完把产物归档到 `dist/1.0.0+N/`，不进 git。
**发布前想清楚在哪台机器出** —— 一旦这个包上传了商店，这个 `+N` 就锁定给它了。

## 五、版本与构建号管理

- 版本号与构建号都在 `flutter_app/pubspec.yaml`：`version: 1.0.0+N`
- `N` 即 Android 的 `versionCode`
- **日常出包不改 `N`**；只在确定要发布时递增
- 递增规则：`N` 要比**商店后台已出现过的最大值**大（不是比 git 里的值大）
- 不确定的话，去 Google Play / 华为后台看已上传的最大 versionCode
- 发布后 commit + push，让另一台机器知道当前进度

## 七、密钥备份要求

密钥现存在于**两台物理机器**，风险面是单机的两倍，请遵守：

1. `.jks` 与 `key.properties` 只通过 **U 盘 / 加密介质 / 密码管理器**传递
2. **不放云盘、不放 git、不截图、不发聊天工具**
3. 其中一台机器重装或报废前，先从另一台确认密钥可恢复
4. 若怀疑泄露：重新生成密钥 → 但**已上架商店的包无法换签名**，只能在换新包名时才能换，所以预防优先于补救
