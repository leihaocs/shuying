# Play 永久买断离线缓存与后续验收

本轮仅修改源码并做静态源码约束检查，未执行 Gradle、Flutter 测试、构建、安装或真实支付。Google Play 当前免费首发配置不变：没有 `PLAY_LICENSE_KEY` 时返回未购买、`purchasesEnabled:false`，不读取缓存解锁，也不能购买或恢复。

## 实现范围

- 缓存内容是 Google 已签名的完整 `Purchase.originalJson` 与 `signature`，只在原有 RSA 验签、包名、永久商品 ID、`PURCHASED` 状态检查和确认购买成功后写入。待付款、取消、未购买、错误签名不会建立新权益。
- 使用 AndroidKeyStore 内不可导出的 AES 256 密钥，随机 IV 的 AES/GCM 加密，附加认证数据绑定应用包名、商品 ID 和格式版本；使用 `AtomicFile` 写入应用 `noBackupFilesDir`。缓存不进入业务 JSON 备份、不导出到其他设备；换机或重装后仍需商店核验。密钥是否由安全硬件保护取决于设备，本实现不声称所有设备都使用 StrongBox。
- `status` 先查询商店，仅连接/查询的临时故障或超时才读取缓存，每次读取仍重新验证 Google 签名、包名、商品和购买状态。商店返回成功后禁用该请求的缓存兜底，确认购买失败也不能使用旧缓存掩盖。
- `restore` 和 `buy` 继续走真实商店通道，不会把读取缓存称作恢复购买成功。`ITEM_ALREADY_OWNED` 也必须由当前商店查询确认为拥有才报告恢复成功。
- 商店成功查询无已确认永久权益时立即通知撤销，并在后台销毁缓存密钥和删除文件。后到的旧确认回调不能重写已撤销缓存或覆盖新权益状态。文件与 KeyStore 访问使用一个后台队列，避免主线程执行加密和磁盘操作。
- `status` 商店等待最多 12 秒，随后缓存读取最多 2 秒；恢复与购买维持原有真实商店等待。缓存缺失、损坏、验签失败、设备密钥不可用时不授予 Pro，提示联网重试。已确认购买不因缓存写入失败被误报付款失败，但该会话不会使用失败的缓存。

## 明确取舍

没有应用账号或已验证的当前 Google 账号 ID，因此没有制造账号 ID、也没有声称缓存已绑定当前 Google 账号。它绑定的是应用在这台设备上的 Keystore。**完全离线时无法得知退款、撤销或切换商店账号**；本机上次已确认的永久权益可在离线时继续使用，待后续成功的商店查询更新。没有为永久买断擅自加离线到期天数。

BillingClient 查询成功表示商店给出结果，不等于本应用执行了独立服务器实时核验。原有本机 RSA 验签与本次加密缓存不能替代服务端 Play Developer API、退款通知或 Voided Purchases API。Google 官方推荐将购买核验和确认移至可信后端；这里沿用现有无账号、本地工具架构，暂不新建付费后端。[Google 购买安全建议](https://developer.android.com/google/play/billing/security)

KeyStore 与文件同时不可写/不可删除时，当前进程立即停止缓存兜底，但不能保证操作系统故障后已经持久撤销旧缓存。损坏设备、Root 后进程被控制也不在“不可伪造客户端权益”的保证范围内。发布前需要按下面矩阵验证缓存失效和持久撤销，不能把静态检查当成支付验收。[Android Keystore 的保护边界](https://developer.android.com/privacy-and-security/keystore)

## iOS 只读核对

现有 `AppDelegate.swift` 的 `entitled()` 遍历 StoreKit `Transaction.currentEntitlements`，只接受 `.verified`、匹配商品且 `revocationDate == nil` 的交易；没有应用自行保存的解锁布尔值。Apple 将事务信息保留在设备并自动同步，适合已有已验证事务的本机权益查询；首次安装、换账号、退款同步及真实飞行模式行为仍需真机验证。手动恢复继续调用 `AppStore.sync()`，不在启动时强制弹认证。本轮未改 iOS 文件。[Apple 本机主动恢复说明](https://developer.apple.com/videos/play/wwdc2022/110404/)、[currentEntitlements](https://developer.apple.com/documentation/storekit/transaction/currententitlements)、[AppStore.sync](https://developer.apple.com/documentation/storekit/appstore/sync())

## 静态检查

`python3 flutter_app/tool/check_play_purchase_cache.py` 只检查关键源码约束，不启动 Android、BillingClient 或 Keystore，不证明 Kotlin 已编译通过或支付结果正确。

## 未来真机验收矩阵（本轮未执行）

| 场景 | 应有结果 |
|---|---|
| 无 Play 公钥、Play 免费首发、direct 渠道 | 保持免费，购买关闭；已有缓存也不能绕过配置 |
| 首次无购买记录，离线启动 | 不解锁；不制造本地权益 |
| 真实已付款、验签通过、确认成功；杀进程后断网重启 | `status` 在商店故障时可验证本机缓存并解锁；购买/恢复仍需要商店 |
| 待付款、取消、验签失败、错误包名或 SKU | 不写入新缓存、不解锁 |
| 商店成功查询无权益或退款后查无权益；再杀进程断网 | 即时取消权益；旧密钥/缓存不能再次解锁 |
| 迟到的旧 ACK 与较新的撤销查询交错 | 旧回调不能重新持久化已撤销的缓存，也不能重新解锁 |
| Activity 重建、旧 BillingClient 回调与新实例查询交错 | 只有最新实例可以修改缓存或交付权益；早先发出的查询不能覆盖后来的购买/撤销 |
| 查询已成功但确认交易失败 | 该请求不使用旧缓存伪称确认成功；后续可通过真实商店重试 |
| 飞行模式下点击恢复购买或购买 | 不通过缓存伪称恢复/购买成功 |
| 文件损坏、截断、改签名、换机复制、密钥丢失 | 不解锁，联网核验后重新建立本机缓存 |
| 缓存写入失败、KeyStore 暂时不可用、缓存删除失败 | 已确认付款不丢；缓存失败不授予新权益；撤销结果不能被后续缓存覆盖 |
| 完全离线时更换 Google 账号/退款 | 明确存在同步延迟；联网后成功商店查询更新，不宣称实时账号绑定 |
| iOS 已购后离线启动、取消、待确认、退款、换账号及手动恢复 | 由 StoreKit 已验证本机权益驱动，分别验证；不从 JSON 恢复权益 |

缓存目录的自动备份排除行为来自 Android `noBackupFilesDir` 的系统约定。[Android 自动备份排除目录](https://developer.android.com/identity/data/autobackup)
