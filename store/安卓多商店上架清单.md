## 一、同一份包能给所有渠道吗？（先讲清楚，避免重复打包）

**答案：除 Google Play 外，国内安卓渠道都可以复用同一份 direct 正式包，不必每个商店打一个包。**

原因：

- `versionCode` 的校验口径是「**这个包名在该商店后台历史上出现过的最高值**」，各商店**独立计数**
- 小米 / 应用宝 / vivo / OPPO / 百度 / 360 你从未上传过任何包 → 历史最大值 = 0 → 本次提交 `5` 完全合规
- 华为那条 `+5` 只约束**华为自身的后续更新**（下次更新要 ≥6），不会扩散到其他商店

> **2026-10-27 更新**：华为 Android 已审核通过并上架，`versionCode 5` **由此被华为正式占用**。
> - 华为后续任何更新包必须 **`+6` 及以上**
> - 小米 / 应用宝 / vivo / OPPO 等**仍可继续用这份 `+5` APK**（它们后台历史为空，互不影响）
- 我们的 direct 渠道**没有接入任何商店 SDK**，所以不需要渠道定制包

**2026-10-28 用户版本号约定（覆盖此前升号建议）**：用户指定正式号 5，所有新编译固定 `1.0.0+6`，三端一致。仅用户明确指定新的正式号后，才调整为新正式号 +1；修复、重提、渠道定制与上传冲突均不授权自行改号。既有 5 号包的渠道投放记录保留历史，不代表新修复已进入该包。

Google Play 使用 `play` flavor 的 `.aab`（含 Play Billing），不能复用 direct APK：

```bash
flutter build appbundle --release --flavor play
```

同号重编按日期批次归档，号冲突报告用户处理。

## 四、逐渠道流程

### 4.1 通用六步（每家都这套）

1. **注册 / 实名**：准备身份证正反面、手机号、邮箱；完成开发者实名（多为个人开发者）
2. **创建应用**：填包名 `com.bookmovie.revisit.app`、名称"书影温故"、分类（工具/效率/图书阅读类中最贴近的）
3. **上传 APK**：传 `dist/1.0.0+5/app-direct-release.apk`，等后台自动解析出包名、版本、签名、权限 → **核对与 §2 一致**
4. **填资料**：图标、截图、简介、介绍、分级问卷、隐私政策 URL、客服邮箱、备案号
5. **传资质**：软著证书（或受理证明）、APP 备案号；核对包名与签名指纹与备案登记一致
6. **提交审核** → 通过后按后台选择上架/发布

> 注意：**不要勾选"独家 / 首发 / 首发联盟"**，否则会限制其他渠道同步上架。
> 商店提供的"加固 / 渠道重签名"可以选，你提交的是原始签名 APK，商店二次签名不影响版本号规则；但加固后要**重新下载安装验收一次**。

### 4.2 各渠道要点

- **小米**：开发平台 → 创建应用 → 上传 APK → 填"软件著作权"栏（等软著）；对个人开发者友好；截图按上传框尺寸（多为 1080×1920）
- **应用宝**：开放平台 → 创建应用；软著/备案必传；注意核对"包名 + 签名 MD5"与备案登记一致
- **vivo**：开发者平台 → 创建应用；隐私政策与权限说明要与实际一致（我们无权限申请是优势）；审核较严
- **OPPO**：**先核实个人主体普通应用准入**，仓库已记录"未确认"，不要想当然；不允许则不申请
- **荣耀**：官方当前不接收个人主体 APK，**暂缓**，不要花时间
- **Google Play**（单独一项）：
  1. Play Console 注册（$25 一次性）→ 完成开发者实名
  2. `flutter build appbundle --release --flavor play` 出 **AAB**
  3. 填数据安全表单：我们可声明**不收集、不共享任何数据**（release 包无 INTERNET 权限）
  4. 内容分级问卷、目标受众、广告声明（无广告）
  5. 目标 API 已满足（targetSdk 36）
  6. **新个人开发者账号通常要求先做封闭测试（约 20 名测试者 / 14 天）才能申请正式发布**，以控制台实际提示为准
  7. Play 的 Billing 商品 `com.bookmovie.revisit.app.pro.lifetime` 需另行配置与测试

## 八、提审后等待与催办（2026-10-27 新增）

### 8.1 先算工作日，而不是自然日

商店审核按**工作日**推进，**周末与法定节假日不排队**。

> 实例：2026-10-23（周五）提交 → 10/26（周一）才算第 1 个工作日，10/27（周二）第 2 个。
> 所以「过了 3 天没消息」实际只过了 **1–2 个工作日**，属于正常等待，不必焦虑也不必催。

### 8.2 各渠道正常时长参考

| 渠道 | 常见时长（工作日） | 说明 |
|---|---|---|
| 华为 Android | 1–3；**首次上架 / 需人工核验资质备案时 3–7** | 我们属首次上架 |
| 华为鸿蒙 | 1–3；同上 | 与 Android 条目**各自独立排队** |
| 小米 | 1–3 | — |
| 应用宝 | 1–3 | — |
| vivo | 1–3，隐私/权限严格时更久 | 我们无权限申请，通常有利 |
| OPPO | 1–3（前提是已确认个人主体准入） | — |
| Google Play | 首次通常 3–7，可能触发人工复核 | 新账号还有封闭测试前置 |
| App Store | 2–5，**首次含内购**通常更久 | 详见《Mac本机构建iOS包与上架.md》 |

以上均为经验参考，**以各后台实际为准**，不构成承诺。

### 8.3 等待期间唯一要做的事：每天 2 分钟自查

```
[ ] 后台应用状态 = 「审核中」（不是「草稿 / 待提交」）
[ ] 消息中心 / 站内信      ← 华为的补料通知常只挂在这里，列表页不红点
[ ] 邮箱（含垃圾箱）：leihaocs@foxmail.com、380174722@qq.com
[ ] 手机短信：备案核验、资质补正常走短信
[ ] 待办 / 需补充资料栏
[ ] 保持登记电话畅通（首次上架可能有人工信审来电）
```

> **唯一需要立刻处理的异常：状态仍是「草稿 / 待提交」** —— 说明上次只是存草稿，没有真正进入队列，需要重新提交。
> 「没有驳回消息」≠「没问题」，补料/驳回常常只出现在消息中心。

### 8.4 绝对不要做

- ❌ **重复提交 / 撤销重提** —— 会重新排队，已经过去的工作日清零
- ❌ 撤回改包重传（除非商店明确要求）
- ❌ 同一时间多家催单（容易把单锁住）

### 8.5 催办阈值

| 已过工作日 | 动作 |
|---|---|
| 0–3 | **什么都不做**，每天自查一次即可 |
| 第 4 个工作日仍无任何状态变化 | 复查上面 §8.3 六个位置，确认确实已进队 |
| 第 5 个工作日仍无变化 | 走官方渠道催办：华为 AGC **在线客服 / 提交工单**，问清卡在哪一环（排队中？资质核验？备案核验？） |
| 收到补料通知 | **一次性补齐**再提交，不要分批（每提交一次重新排队） |
