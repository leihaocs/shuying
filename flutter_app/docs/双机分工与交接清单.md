# 双机分工与交接清单（Windows ⇄ macOS）

> **回答的问题**：在这台 Windows 电脑上现在能做哪些事，且**不会**影响回家在 Mac 上继续？
> **结论**：除「生成平台目录」和「iOS 打包/证书」两件事外，**其余全部可以在这台 Windows 上做完**。
> 把 Windows 当"办公机"（账号、资质、备案、材料、文档），把 Mac 当"构建机"（Xcode、平台目录、出包）。

---

## 0. 一条判断标准

> **这件事产出的东西，会不会被"某台机器"绑定？**

| 会绑定 | 不会绑定 |
|---|---|
| Xcode 钥匙串里的证书、`android/` `ios/` `ohos/` 平台目录、`key.properties` 里的绝对路径、`.ipa` 产物 | 网页后台的账号/实名/备案、Word 文档、公网 URL、git 仓库里的文本、`lib/` 代码 |

**不会绑定的 → 现在就在 Windows 上做完。会绑定的 → 留到 Mac。**

## 4. 平台目录：只生成一次（重要决策）

`android/` `ios/` `ohos/` 是 `flutter create` 的产物，**一旦提交进 git，两台机器共享同一份**。
若两台机器各自生成一次，git 会看到两份不同的模板文件，出现大量无意义冲突。

> ⚠️ **本项目采用方案 A**：三端（**含安卓**）全部在 Mac 上生成。
> 这台 Windows **永远不生成** `android/` `ios/` `ohos/`，只做 §2 的"办公类"工作。
> 安卓签名证书由 Mac 生成后导入本机（见 §6）；本机 `git pull` 拿到 `android/` 后**可以**出安卓包，
> 但这只是加分项 —— 一旦出包异常就别折腾，出包一律回 Mac，主线优先。

### 方案 A ✅（**本项目采用**）：只在 Mac 生成

- Mac 上 `./tool/bootstrap.sh com.bookmovie.revisit.app` 一次出三端
- Windows 上**永远不碰** `android/` `ios/` `ohos/`
- Windows 只做 §2 的"办公类"工作 + 编辑 `lib/` `docs/`
- Mac 提交后 Windows `git pull` 即可拿到 `android/`（可出安卓包，加分项）

### 方案 B：分机器生成，互不重叠（**未采用**）

- Windows 生成 `android/`：`flutter create --platforms=android --org com.bookmovie.revisit --project-name app .`
- Mac 生成其余：`flutter create --platforms=ios,ohos --org com.bookmovie.revisit --project-name app .`
- ⚠️ 不采用的原因：Mac 要出鸿蒙就得用**鸿蒙版 Flutter SDK**，它生成的安卓模板
  （AGP / Gradle / Kotlin 版本）与本机 3.47.5 不同。安卓是主线之一，
  必须让 Mac 用它自己的 SDK 生成 `android/`，否则会在主力机器上踩版本坑。

> 无论哪个方案：**`flutter create` 每台机器只跑一次，之后 `--overwrite` 要谨慎。**

## 5. 危险操作黑名单

| 别做 | 后果 |
|---|---|
| ❌ 在 Mac 上跑 `./tool/gen-keystore.sh`（不带 `--check`） | 生成新密钥 = App 永远无法覆盖安装 + 备案作废（脚本已拦截，需输入 `GENERATE-NEW-KEY`） |
| ❌ 把 `.jks` / `key.properties` 提交进 git | 密码与私钥泄漏（`.gitignore` 已配好，别强行 `-f`） |
| ❌ 两台机器各跑一次 `flutter create` | 平台目录冲突（见 §4） |
| ❌ 在这台 Windows 上跑 `flutter create` 生成平台目录 | 方案 A 下三端都由 Mac 生成；本机生成会和 Mac 抢 `android/`，且模板版本不一致（见 §4） |
| ❌ 在 Windows 上跑 `flutter create --platforms=ios` | 直接失败，且可能留下半个工程 |
| ❌ 用微信/QQ 传 `.jks` | 密钥经第三方服务器，等于交出签名权 |
| ❌ 提交备案后不盯手机 | 12381 短信 24 小时内没回复 → 驳回重来 |

## 6. 交接清单（钥匙方向：Mac 生成 → 导回这台 Windows）

### 6.1 在 Mac 上生成（主线）

| 物件 | 说明 |
|---|---|
| 签名密钥 | Mac 上 `./tool/gen-keystore.sh` → 生成 `~/keys/shuyingwengu-release.jks` |
| keystore 密码 | 生成时设置，存密码管理器；**不要**写进任何会提交的文件 |
| 登记表 | 生成后**手动**把 MD5/SHA1/SHA256 填回 `tool/keystore-fingerprint.txt` 并提交（脚本只打印、不自动写回） |
| 工程源码 | Mac `git clone` 即可（仓库根是 `APPdev`，`flutter_app` 是子目录） |

### 6.2 导回这台 Windows（加分项）

```powershell
git pull                                        # ★ 先拉，拿到 Mac 提交的新指纹
copy <U盘>:\shuyingwengu-release.jks C:\Users\joy-rd2\keys\
powershell -ExecutionPolicy Bypass -File tool\gen-keystore.ps1 -Check
# 期望输出：✅ 一致：这份 .jks 就是本项目的正式密钥
```

| 物件 | 怎么带 |
|---|---|
| 签名密钥 | U 盘 + 网盘各一份（**双备份**）；❌ 不用微信/QQ（经第三方服务器 = 交出签名权） |
| 登记表 | **走 git**（`git pull`），不靠 U 盘 |

### 6.3 ★ 必须做：处理 Windows 上的旧钥匙

Mac 的新钥匙确认可用后，**删掉或改名归档**这台机器上的旧钥匙：

- `C:\Users\joy-rd2\keys\shuyingwengu-release.jks`（旧）

⚠️ 两台机器各留一把 = 「两把钥匙」灾难：签名不一致 → 无法覆盖安装、备案对不上。
**在确认新钥匙能正常构建之前，先别删**（改名成 `old-20260923.jks.bak` 更稳妥）。

### 6.4 不要带（Mac 会重建 / 走 git）

- `build/`、`.dart_tool/`、`.flutter-plugins-dependencies`（构建缓存，几百 MB）
- `android/key.properties`（含**本机绝对路径**，各机器自己生成）
- `android/` `ios/` `ohos/`（Mac 生成后走 git，本机 `git pull` 即可）

> ⚠️ 工程已在 git 里，仓库根是 `d:\Codes\APPdev`（不是 `flutter_app`）。
> **不要**在 `flutter_app` 里再跑 `git init`，会形成嵌套仓库。

## 7. 回家后 Mac 上的首次操作顺序

```bash
# 1. 取代码
git clone <私有仓库地址> shuyingwengu && cd shuyingwengu/flutter_app
#    （或从 U 盘拷贝工程目录）

# 2. 依赖
flutter pub get

# 3. 生成三端平台目录（★ 安卓也在这一步出，一次出齐）
chmod +x tool/bootstrap.sh
./tool/bootstrap.sh com.bookmovie.revisit.app
#    若鸿蒙版 Flutter SDK 没装：flutter create --platforms=android,ios \
#      --org com.bookmovie.revisit --project-name app --overwrite .

# 4. 放密钥并校验（★ 关键：不要重新生成）
cp /Volumes/<U盘>/shuyingwengu-release.jks ~/keys/
./tool/gen-keystore.sh --check
#    期望输出：✅ 一致：这份 .jks 就是本项目的正式密钥
#    同时会自动写出 macOS 路径的 android/key.properties

# 5. 核对三端标识符都等于 com.bookmovie.revisit.app
grep applicationId android/app/build.gradle.kts
grep bundleName ohos/AppScope/app.json5
grep PRODUCT_BUNDLE_IDENTIFIER ios/Runner.xcodeproj/project.pbxproj | head -3
```
