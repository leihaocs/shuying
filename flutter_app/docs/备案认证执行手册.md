# 备案认证执行手册（一步一步照着做）

> **范围**：主体确定 → 账号实名 → 证书与特征信息 → 软著/电子版权 → 域名服务器 → App 备案 → 隐私政策 → 备案后维护。
> **性质**：本手册只给**顺序、依赖、动作、材料**，每步一勾；背景原因与细节见：
> - 软著材料排版、备案表单字段：[`上架前置资质与备案指引.md`](上架前置资质与备案指引.md)（下称"指引"）
> - 开发者账号注册细节：[`三端开发者注册与上架执行流程.md`](三端开发者注册与上架执行流程.md)（下称"流程"）
> - **哪台机器做哪些事（Windows / macOS 分工与交接）**：[`双机分工与交接清单.md`](双机分工与交接清单.md)
>
> **预估**：全程 3~6 周（大头是等待）；现金约 100~200 元/年（域名+服务器）+ 可选软著代办 0~1500 元 + Apple 688 元/年（仅 iOS）。

## 总依赖图（为什么是这个顺序）

```
阶段0 主体/名称/邮箱（定死不改）
  │
  ├─► [1] 账号实名：华为联盟(免费) / 云厂商(免费) / Apple(688元,仅iOS)
  │        │
  │        ├─► [3A] Android .jks 密钥 ──► MD5 + 公钥 ─┐
  │        ├─► [3B] iOS 证书(依赖Apple账号) ─► SHA-1 ─┼─► [6] App备案 ─► 备案号
  │        └─► [3C] 鸿蒙证书(依赖华为实名) ──► MD5 ──┘      ▲
  │                                                     [2] 域名实名(3~5天)
  │                                                          + 服务器≥3个月 + 备案服务码
  ├─► [4] 软著/电子版权（等待最久，D1 就提交）──► 商店上架门槛
  └─► [5] 隐私政策 URL（1 小时）──────────► 商店审核 + 备案表单
```

**关键结论**：
- 阶段 1、2、4、5 可以**同一天全部启动**（D0）。
- 阶段 6（提交备案）的前置 = 域名实名通过（3~5 天）+ 至少一个平台的证书信息（附录 A）。
- **软著不阻塞备案**（两线并行），但阻塞商店提审。

## 阶段 0：三个决定（10 分钟，一旦定死全程不改）

- [ ] **0.1 主体**：个人 / 企业。
  > 软著、备案、商店认证**三者主体必须一致**；个人可行且最省事，企业需对公账户。
- [ ] **0.2 名称**：按上方身份卡，三处（软著/备案/商店）完全一致。
- [ ] **0.3 联系方式**：设一个专用邮箱 + 确认本人实名手机号。
  > 备案提交后**工信部 12381 短信核验必须 24 小时内回复**，错过即驳回，全程盯着这个手机号。

## 阶段 1：账号注册与实名（D0~D2，先启动等待期长的）

- [ ] **1.1 华为开发者联盟**（免费）：注册 + 个人实名（身份证+人脸）。
  > 一个账号同时覆盖：鸿蒙证书（阶段 3C）+ 华为应用市场 + AGC。指引见"流程"2.2。
- [ ] **1.2 云厂商**（免费）：注册**中国站**账号（阿里云或腾讯云，选一家，备案就绑这家）+ 个人实名。
  > ⚠️ 阿里云**国际站**不支持 App 备案，必须中国站。
- [ ] **1.3 Apple（仅 iOS 上架才需要，688 元/年）**：Apple ID 开双重认证 → Apple Developer App 内身份验证（身份证+人脸）→ 付费。
  > 实名审核要 1~2 天，想 iOS 与安卓**同时备案一次过**就 D0 启动；
  > 想省钱/不急 iOS，可先只备安卓+鸿蒙，iOS 证书下来后走「变更备案」补平台（见阶段 7）。
- 小米 / OPPO / vivo / 荣耀 / 应用宝：**等软著/电子版权到手再注册**（注册时就要传证书）。

### 3A Android（最快，只要 JDK，不需要 Android Studio）

> ⚠️ **已定案：这台 Windows 不参与任何出包。**下面标「Mac」的步骤都在 Mac 上做，
> 本机只负责冷备份与 `-Check` 校验。

- [x] **正式密钥已由 Mac 生成**（2026-09-28）：`~/development/keys/shuying-release.jks`，alias `shuyingwengu`
  > 第一版 Windows 密钥（`C:\Users\joy-rd2\keys\shuyingwengu-release.jks`，alias `shuying`）
  > **已作废**（改名为 `.bak` 保留）。作废时项目尚未发布任何版本，更换零成本；
  > **正式发布后本密钥不可再更换。**
- [x] **签名证书指纹已登记** `tool/keystore-fingerprint.txt`（MD5/SHA1/SHA256）
  - Android 备案用的 MD5：`95:D2:D6:AF:26:3D:54:02:75:E8:09:05:F7:5F:0C:FD`（附录 A 已用此值）
  > 工程里**永远不存** `.jks` 和 `key.properties`（都在 `.gitignore`），但有这份指纹登记表当"门神"——
  > 生成脚本会读它，发现本机没密钥但登记存在 → 拦截手滑；`-Check` 用于拷过来后校验。
- [ ] **异地备份 .jks**（网盘 + U 盘两处，在 Mac 上操作）。**丢了 = App 永远无法更新。**
- [ ] **拷一份回这台 Windows 做冷备份**，并验证指纹一致（本机已装 JDK 17，够跑这个校验）：
  ```powershell
  powershell -ExecutionPolicy Bypass -File tool\gen-keystore.ps1 -Check -Jks <拷回来的路径>
  ```
- [ ] **改密码**（生成时是随机强密码，建议换成自己记得住的）——Mac 上跑：
  ```bash
  keytool -storepasswd -keystore ~/development/keys/shuying-release.jks
  keytool -keypasswd   -keystore ~/development/keys/shuying-release.jks -alias shuyingwengu
  ```
  改完后同步更新 Mac 上 `android/key.properties` 的两行密码。**指纹和公钥都不会变**，
  不影响备案已填的信息。
- [ ] ~~在这台 Windows 上构建正式 APK~~ —— 已取消，出包一律在 Mac（见 `双机分工与交接清单.md` §2.7）。
